实例是怎么识别出来的

① 后端 /node 接口（最可靠）：请求后端 /node，返回的 nodeName 就是实例名，同时给出 cacheStore / redis 缓存落点。
② 响应头：页面用 fetch(location.href, {method:'HEAD'}) 读自己的响应头，若 Nginx 注入了 X-Instance，直接用它。
③ 端口推断（直连时可用）：直接访问 http://ip:8081 这类地址时，按端口推断成实例。
④ 手动标记（兜底）：以上都取不到时，手动填一次，本机记住。
四条都取不到，说明 /node 路径不对、且 Nginx 没配 X-Instance，按下面的片段补上即可。

关于环境：原计划的 Tomcat 9 集群已下线 —— 后端是 Spring Boot 3（jakarta），Tomcat 9 是 javax，war 包打不进去。现在改成同一份 jar 起 3 个实例：node-1:8082 / node-2:8083 / node-3:8084，Nginx 在上面做分发。页面标题保留"Tomcat"是为了对上实验编号，实际验证的是 Spring Boot 实例。

给周泓颖的 Nginx 配置片段

加了这一行，页面就能自动识别实例 
# nginx.conf —— upstream 与 add_header
upstream tomcat_cluster {
    # 负载策略按周泓颖的方案选一种，其余注释掉
    # ip_hash;                          # 策略一：IP 哈希
    # least_conn;                       # 策略二：最少连接
    # fair;                             # 策略三：fair（需第三方模块）
    server 192.168.1.11:8080 weight=1;  # 策略四：加权轮询（默认）
    server 192.168.1.12:8080 weight=1;
    server 192.168.1.13:8080 weight=2;
}

server {
    listen 80;
    server_name _;

    location / {
        proxy_pass http://tomcat_cluster;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # 关键：把上游实例名回写给前端
        add_header X-Instance $upstream_addr always;
        add_header X-Upstream-Status $upstream_status always;
    }
}
$upstream_addr 的值形如 192.168.1.12:8080，本页会把它显示成实例名（也可以再加一条 map 把它映射成 tomcat-02）。always 不能省，否则 4xx/5xx 响应不带这个头，页面就识别不出来。
