### 后端返回字段（前端已按此适配）

- 聊天 `chat_message`：`id / senderId / receiverId / msgContent / msgImage / isAiMessage / readFlag / riskHint / createTime`
  - `fromUserId` 由后端从 token 取，前端不传、也伪造不了
  - 进会话后端自动把"对方发给我"的未读标成已读，前端不用另调
  - 错误码：401 无 token；400 缺 `receiverId` / 发给自己 / 内容全空
- 订单：`id / orderNo / goodsId / price / orderStatus / createTime`，字典 `WAIT_CONFIRM / WAIT_TRADE / FINISH / CANCEL`
- **后端没有 pay 接口** —— `MyOrders` 原来的"去付款"已改为"取消订单"（`PUT /order/cancel/{id}`），"确认收货"接 `PUT /order/confirm/{id}`

### 原待后端补的两项，已实测补齐

1. **商品上下架**：已确认接口为 `PUT /api/v1/goods/{id}/status?status=ON_SHELF|OFF_SHELF`，参数名是 **`status`**（query 传，不是 `goodsStatus`）。前端 `MyPublishes` 已接该接口，实测自己商品下架、上架均返回 `code=1 操作成功`；改他人商品返回 `code=500 无权操作别人的商品`，鉴权正常。
2. **收藏添加路径**：已确认为 `POST /api/v1/goodsCollect/add?goodsId={id}`（`goodsId` 走 query，不是请求体）。实测 `add` 成功 → `GET /goodsCollect/has/{id}` 为 true → `DELETE /goodsCollect/{id}` 取消 → `has` 为 false；重复收藏返回「已经收藏过该商品」。

> 另：公开列表 `GET /goods/list` 支持 `keyword`（标题 + 描述 LIKE，四个参数名 `keyword/kw/title/searchKey` 均可用），只在 `PASS + ON_SHELF` 范围内过滤；商品卡片交易地点取自 `tradePlace`，后端已修复该字段丢失问题。
