## 零、演示前 30 秒准备

1. 后端启动：`http://localhost:8090`，接口前缀 `/api/v1`
2. Redis 已起（验证码、token 黑名单都放这里）
3. 前端启动：
   ```powershell
   cd D:\ruanjiangongcheng\campus-market
   npm run dev
   ```
4. 浏览器打开 `http://localhost:5173/campus-market/`
5. **确认 `USE_MOCK` 开关**（`src/api/config.js`，已改成环境变量控制，默认 `true`）：
   - 不启后端、纯前端演示：什么都不用设，直接 `npm run dev`
   - 要打真实后端：PowerShell 里先 `$env:VITE_USE_MOCK="false"; npm run dev`，并确认 `http://localhost:8090` 能访问
   - 后端在别的电脑上：再加 `$env:VITE_BACKEND="http://192.168.x.x:8090"`
   - 演示时必须说清楚当前是哪种，不要含糊

## 二、分步操作（照着点）

### 第 1 步：注册（`/register`）

1. 首页右上角 →「登录」→ 登录页底部「还没有账号？立即注册」
2. 学号先填 `123` → 点注册 → **报错"学号格式不正确（8-12 位数字）"**
   - 讲解词：前端逐字段校验，不等后端返回错误
3. 学号填 `2024999999`，手机号填 `13700000000`，密码 `123456`，确认密码 `123455`
   → **报错"两次输入的密码不一致"**
4. 改回一致 → 提交 → **提示"注册成功，请登录"**
5. 再注册一次同一学号 → **提示"该学号已注册"**（演示查重）

### 第 2 步：登录（`/login`）

1. 回到登录页，默认是「账号密码」Tab
2. 用户名 `2024110640`，密码 `123456`，验证码**故意填错** → **提示"验证码错误"**，且验证码图自动刷新
   - 讲解词：验证码一次性，失败即作废，必须换一张
3. 点验证码图片可以手动换一张
4. 按图填对 → 登录成功 → 自动回跳（如果是从别的页面跳来的，会回原页面）
5. 讲一下三个 Tab：
   - 「短信登录」：界面已做，等后端短信通道，目前演示用内置账号
   - 「扫码登录」：界面 + 占位，按分工这一项只做形态
   - 底部有测试账号提示条，评委问账号直接指这里

### 第 3 步：管理员视角（重点）

用 `2024110640 / 123456` 登录后：

1. 顶部导航出现 **「管理后台」** 入口
2. 点进 `/admin`，左侧 5 个菜单都在：用户管理 / 商品审核 / 分类管理 / 举报处理 / 角色权限
   - 讲解词：菜单不是写死的，是后端 `/user/menus` 下发 + 前端按 `perms` 过滤
3. 进「角色管理」→ 点某个角色「分配权限」→ **Element Plus 树形勾选**，勾完确定
   - 讲解词：菜单权限（`permType=1`，存 URL）+ 按钮权限（`permType=2`，存权限码），父节点半选也落库，否则菜单不显示
4. 进「用户管理」→ 点「封禁」→ 二次确认 → 状态变「已封禁」
   - 讲解词：这个按钮带 `v-permission="'user:status'"`，没有这个权限码的账号根本看不到按钮

### 第 4 步：普通学生视角（对比）

退出，用 `2024110601 / 123456` 登录（或自己刚注册的账号）：

1. 顶部导航**没有「管理后台」**
2. 个人中心页**没有管理员黄色横幅**
   - 讲解词：普通学生就是用户，管理后台不给普通学生看，这是按闲鱼那种"用户/后台分开"的流程做的
3. 手动在地址栏敲 `http://localhost:5173/campus-market/admin`
   → **被守卫拦回首页，弹出"当前账号没有管理后台访问权限"**
   - 讲解词：前端拦一层，后端 `AuthInterceptor` 再拦一层返 403，双保险
4. 讲后端那句：普通学生直接调 `/api/v1/roles` 返回 **403**

### 第 5 步：退出登录

1. 个人中心 →「退出登录」→ 二次确认 →「已退出登录」
2. **按 F12 → Network**，找到 `logout` 请求，状态 200
   - 讲解词：不是只删本地 token，是真调 `POST /api/v1/auth/logout`，后端把 token 写进 Redis 黑名单
3. 退出后刷新页面 → **直接跳回登录页**（不是还能看到首页内容）
4. 讲验证：把退出前的旧 token 手动拿去调接口 → **401**

### 第 6 步：忘记密码（`/forgot`）

1. 登录页 →「忘记密码？」
2. 三步步骤条：填手机号 → 验短信码 → 设新密码
3. 手机号填 `13900000000` → 获取验证码 → 60 秒倒计时
   - Mock 模式会把验证码回显在提示里，方便演示；真实环境是发短信
4. 填码 → 设新密码 `654321` → 提示"密码已重置"
5. 回登录页用新密码登录 → 成功

### 第 7 步：业务页走查（证明"每个跳转页都有实现"）

按这个顺序点，每一页都能返回、都能操作：

1. 首页 → 搜索框输入「教材」→ 回车 → 商品市场带关键词
2. 商品市场 → 分类标签切换 → 点商品卡进详情
3. 详情页 → 收藏 / 取消收藏 / 点「举报」→ 进举报页选原因提交
4. 详情页左上「返回」→ 回列表
5. 右上角「＋ 发布」→ 发布页填完提交 → 回市场能在列表看到新商品
6. 个人中心 →「我的发布」→ 下架/上架切换
7. 「我的收藏」→ 取消收藏
8. 「我的订单」→ 三色状态标签（待付款/待交易/已完成）
9. 右下角 **AI 悬浮球** → 进 AI 助手页 → 输入一句话有回复

## 四、演练时的注意事项（避免现场穿帮）

1. **不要说"全部功能都连了后端"**：我的发布 / 收藏 / 订单 / 聊天 / 举报的页面和接口层都已接上真实路径（`/goods/my`、`/goodsCollect/my`、`/order/myBuy`、`/chat/messages`、`/report/add`），但 `USE_MOCK=true` 时走的是本地演示数据；`AI 助手` 仍是关键词假回复。被问到照实说"接口路径已对齐后端，开关切 false 就走真实接口；AI 助手没接模型"。
2. **`USE_MOCK` 默认 `true`，不要讲"数据来自 MySQL"**：说"当前是 Mock 通道，设 `VITE_USE_MOCK=false` 走真实接口"，这个开关是按分工保留的。
3 **验证码演示别卡住**：Mock 模式下验证码是随机生成的图，看准了再填；填错会自动刷新，重填一次即可。
4. **退出后一定要刷新页面**再讲"回登录页"，否则看不出效果。
5. **两台机器演示要改代理**：已改成环境变量，`vite.config.js` 默认 `http://127.0.0.1:8090`；后端在演示机上就设 `$env:VITE_BACKEND="http://<演示机IP>:8090"`，不用改代码。
6. **后端没有"付款"接口**：订单页的"待付款"按钮文案是"取消订单"，对应 `PUT /order/cancel/{id}`；"确认收货"对应 `PUT /order/confirm/{id}`。别现场说"点付款"。
